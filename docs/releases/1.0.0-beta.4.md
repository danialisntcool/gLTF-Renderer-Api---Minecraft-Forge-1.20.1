# glTF Renderer API 1.0.0-beta.4

For Minecraft Forge 1.20.1.

## Fixes

- Fixed normal-map details disappearing as the camera moves closer to a model.
- Fixed inventory PBR reflections depending on the world camera or inventory slot position, and improved GUI lighting.
- Improved texture mipmapping and minification, including fallback filtering for KTX textures without mipmaps.
- Hardened render-state restoration around native rendering and cached inventory icons.
- Prevented creative-tab population from accessing unavailable test-item registry entries.

## Performance

- Added bounded caching for eligible static inventory icons. Animated, translucent and custom-material models continue rendering live.
- Added opt-in world batching through `GltfApi.renderWorld`, used by the supplied entity and block-entity renderer helpers.
- Improved indexed native GPU instancing for matching opaque/masked batch requests.
- Reused compatibility buffers, instance arrays, staging storage and static vertex attributes to reduce allocation and draw overhead.
- Shared exact animation-pose, skin-matrix and deformation work where states match.
- Improved transparency sorting reuse without boxed triangle sorting.
- Added conservative animation-aware model bounds and helper render-distance controls.

## Materials and API

- Added material-aware buffered PBR rendering with shaders off, including metallic/roughness, normal, occlusion and emissive properties.
- Metallic reflections use one reusable mipmapped environment panorama, not real-time scene reflection passes. Resource packs can override the panorama.
- Added explicit render-path selection, custom material rendering hooks and static item-model replacement helpers.
- Preserved Oculus entity shader IDs for eligible queued rendering. Shadow passes, unsupported adapters and special render contexts retain immediate rendering.

## Profiling

- Added operator-only `/gltfprofile start 20`, `/gltfprofile status` and `/gltfprofile stop` commands to profile actual world and inventory rendering without spawning synthetic models.
- Reports frame-time percentiles, API CPU submission, covered GPU timing, draws, instancing, uploads, vertex transforms, cache reuse and culling counters.
- Expanded the existing benchmark with explicit native/buffered path choices and rendering counters.

## Notes

- Custom renderers must opt into `renderWorld` to use deferred world batching; existing `renderBuffered` callers are not automatically moved into the queue.
- Shader packs retain Minecraft's compatible rendering stream. Automatic conversion to arbitrary shader-pack PBR conventions is not included.
- Large block-entity models still require a suitable consumer-provided `getRenderBoundingBox()` for Forge's earlier visibility checks.
- Automatic LOD generation and behind-wall occlusion are not included in this update.
- No Quantified or Luxium dependency is required.
- The public rendering API remains client-side. Client preferences and release cache limits are configurable.
